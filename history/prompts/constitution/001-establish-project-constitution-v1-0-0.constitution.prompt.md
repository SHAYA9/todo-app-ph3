## Core Principles

### I. Spec-Driven Infrastructure (NON-NEGOTIABLE)
All infrastructure must be defined via specifications.

### II. Application Code is Immutable

This phase focuses strictly on deployment and infrastructure.

### III. Containerization First
Frontend and backend applications must be containerized using Docker.
Use Docker AI Agent (Gordon) if available; otherwise generate standard Docker artifacts.

### IV. Kubernetes via Helm
All Kubernetes resources must be deployed using Helm charts.
Raw kubectl apply is prohibited unless generated via AI tooling.

### V. AI-Assisted DevOps
kubectl-ai and kagent must be used for Kubernetes operations, diagnostics, and optimization.
AI-generated commands must be documented.

### VI. Local Cluster Only
Deployment target is Minikube.
No cloud providers are allowed in this phase.

## Constraints
- Use existing frontend, backend, and chatbot code
- No database schema changes
- No business logic changes
- Docker Desktop + Minikube required

## Success Criteria
- Frontend and backend run as Kubernetes pods
- Helm chart deploys successfully
- Frontend accessible via Minikube
- Chatbot functionality works end-to-end

## Governance
This constitution overrides all prior development practices.
Any change requires spec refinement and regeneration.
